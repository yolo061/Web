# 文件读写：对同一个文件既读又写 —— 注销过程（教材 2.9 节，书 P54–58）

> who 是从文件**读**数据；cp 是从一个文件读、写往另一个文件。那**对同一个文件既读又写**是什么情形？
> 典型例子就是"注销"：注销程序要修改 utmp 文件里属于自己终端的那条登录记录——先读出来找到它，再改写回去。

## 一、注销过程做了些什么（2.9.1，P54）

注销（logout）时，系统会改变 utmp 中相应的登录记录。可以自己动手观察（教材的实验步骤）：

1. 从另外一个窗口登录到一个 Unix 系统；
2. 运行前面编写的 who1，查看 utmp 中与你登录相关的记录（注意自己用的是哪个终端，如 `tty2`）；
3. 注销其中一条；
4. 再运行 who1，对比变化。

会发现：那条记录的用户名变了（有的系统直接被清空），`ut_time` 也变成了注销时刻。本质上就是这条记录的 **`ut_type` 从 `USER_PROCESS` 被改成了 `DEAD_PROCESS`**——这也正好解释了 who2 里为什么要过滤 `ut_type != USER_PROCESS`：注销过的记录还留在文件里，只是类型变了。

## 二、注销过程如何工作：4 个步骤（2.9.2，P54–55）

| 步骤 | 做什么 | 用的调用 |
|---|---|---|
| 1 | 打开文件 utmp | `open(UTMP_FILE, O_RDWR)` |
| 2 | 从 utmp 中找到包含你所在终端的登录记录 | `read` 循环 + `strcmp` |
| 3 | 对当前记录做修改，并写回原处 | `lseek` + `write` |
| 4 | 关闭文件 | `close(fd)` |

### 第 1 步：为什么是 O_RDWR

who 只读，用 `O_RDONLY` 就够；注销程序既要**读**（找到登录记录）又要**写**（修改它），所以必须读写方式打开：

```c
fd = open(UTMP_FILE, O_RDWR);
```

（`O_RDWR` = Open READ + WRITE，可读可写，就是上一轮说的三种基本模式之三。）

### 第 2 步：找到自己终端的那条记录

在 while 循环中读取一条条 utmp 记录，把它的 `ut_line` 字段跟你的终端名做比较，相等就调用修改函数：

```c
while ( read(fd, &rec, utmplen) == utmplen )    /* get next record */
    if ( strcmp(rec.ut_line, myline) == 0 )      /* what, my line? */
        revise_entry();                          /* remove my name */
```

### 第 3 步：修改记录 —— 以及一个棘手的问题

要做的修改很简单：把 `ut_type` 从 `USER_PROCESS` 改成 `DEAD_PROCESS`，把 `ut_time` 改成注销时间（当前时间），有的版本还会把用户名和远程主机字段清空。

**但怎么把修改过的记录写回文件？** 直接用 `write` 不行——`write` 只会写到**下一条**记录的位置，而不是刚才读到的那条。因为系统每次打开文件都保存一个**位置指针**，读写操作完成时指针会自动移到下一个记录位置。

> **问题**：文件操作中，如何改变一个文件的当前读/写位置？
> **答案**：使用系统调用 `lseek`。

### 第 4 步：关闭文件

`close(fd);`

## 三、lseek：改变文件的当前位置（2.9.3，P55–56）

内核为**每个打开的文件**保存一个位置指针（图 2.8）：读数据时从指针处读入指定长度，然后指针后移到未读数据处；写也一样。

注意：**指针与文件描述符相关联，而不是与文件关联**。两个程序同时打开同一个文件，各有两个指针，对文件的读写不会互相干扰。

**lseek 用法**：

| 项目 | 内容 |
|---|---|
| 目标 | 使指针指向文件中的指定位置 |
| 头文件 | `#include <sys/types.h>`、`#include <unistd.h>` |
| 函数原型 | `off_t oldpos = lseek(int fd, off_t dist, int base)` |
| 参数 | fd 文件描述符；dist 移动的距离；base 基准 |
| base 取值 | `SEEK_SET` ⇒ 文件的开始；`SEEK_CUR` ⇒ 当前位置；`SEEK_END` ⇒ 文件结尾 |
| 返回值 | −1 遇到错误；oldpos 指针变化**前**的位置 |

`base` 是基准位置，`dist` 是从基准开始的偏移量（**可以是负数**）。几个例子：

```c
lseek(fd, -(sizeof(struct utmp)), SEEK_CUR);
/* 把指针往前移回一个 utmp 结构 */

lseek(fd, 10 * sizeof(struct utmp), SEEK_SET);
/* 指到第 11 个记录的开始位置 */

lseek(fd, 0, SEEK_END);
write(fd, "hello", strlen("hello"));
/* 指到文件末尾，然后写入一个字符串 */

lseek(fd, 0, SEEK_CUR);
/* dist 为 0 时不移动，返回值就是指针当前指向的位置 */
```

## 四、编写终端注销的代码（2.9.4，P57）

书上给出的参考函数 `logout_tty`：

```c
/*
 * logout_tty( char * line )
 * marks a utmp record as logged out
 * does not blank username or remote host
 * return -1 on error, 0 on success
 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <time.h>
#include <fcntl.h>
#include <unistd.h>
#include <utmp.h>

int logout_tty( char * line )
{
    int          fd;
    struct utmp  rec;
    int          len = sizeof( struct utmp );
    int          retval = -1;                        /* pessimism */

    if ( ( fd = open( UTMP_FILE, O_RDWR ) ) == -1 )  /* open file */
        return -1;

    /* search and replace */
    while ( read( fd, &rec, len ) == len )
        if ( strncmp( rec.ut_line, line, sizeof( rec.ut_line ) ) == 0 )
        {
            rec.ut_type = DEAD_PROCESS;              /* set type */
            if ( time( &rec.ut_time ) != -1 )        /* and time */
                if ( lseek( fd, -len, SEEK_CUR ) != -1 )   /* back up */
                    if ( write( fd, &rec, len ) == len )   /* update */
                        retval = 0;                  /* success! */
            break;
        }

    /* close the file */
    if ( close( fd ) == -1 )
        retval = -1;
    return retval;
}
```

逐层看懂这段代码：

1. `retval = -1` 起名叫 pessimism（悲观）：先假设会失败，只有整条链路全部成功才置 0；
2. 循环逐条读记录，`strncmp( rec.ut_line, line, sizeof(rec.ut_line) )` 整个字段级比较，找到 `ut_line` 等于参数 `line` 的那条；
3. 命中后三层嵌套 if 一环扣一环：改 `ut_type` → `time()` 把 `ut_time` 设为当前时间 → `lseek(fd, -len, SEEK_CUR)` **往回退一条记录**（回到刚读过的这条的开头）→ `write` 把改好的记录覆盖回去，任何一步失败 retval 都保持 -1；
4. 处理完 `break` 跳出循环（只需改一条）；
5. `close` 失败也要把 retval 打回 -1。

书上特意说明（P57）：**这里对每个系统调用都做出错处理是很有必要的**——因为这个程序要修改重要的系统配置文件，utmp 写坏了整个系统都会麻烦。另见 2.10 节：系统调用出错时内核通过全局变量 `errno` 报告错误类别（如 `ENONENT` 文件不存在、`EACCES` 无权限），`<errno.h>` 里有错误代码表，可以按错误类型做不同处理。

## 五、怎么测试

`logout_tty` 是个函数，写个小 main 调用它，然后运行自己的 who 观察效果：

```c
int main(void)
{
    /* 传入你的终端名，如 "tty2"（先在另一个终端用 who 命令确认） */
    return logout_tty("tty2");
}
```

```
$ cc io.c -o io
$ ./io            # 注销指定终端
$ ./who           # 对比：那条记录应从输出里消失
```

**两点务必注意（现代 Linux）：**

1. **先用副本练习**：把 utmp 复制一份到自己目录，代码里把 `UTMP_FILE` 临时换成副本路径练手，确认逻辑无误再动真文件；
   ```sh
   cp /var/run/utmp /tmp/my_utmp
   ```
2. **真文件需要权限**：`/var/run/utmp` 属于 root:utmp、普通用户只读，直接对它 `open(O_RDWR)` 会返回 -1（errno = EACCES）——这本身就是 2.10 节说的错误处理的一次实战。真机测试用 `sudo ./io`。

## 六、现代 Linux 上的兼容性说明

- `time(&rec.ut_time)`：本机 `ut_time` 是 `int32_t`（见 `bits/utmp.h` 的 `ut_tv.tv_sec`），而 `time()` 的参数是 `time_t *`（即 `long *`），直接传 `&rec.ut_time` 编译器会警告指针类型不匹配。稳妥写法是先用 `time_t` 临时变量接住再赋值：
  ```c
  time_t t = time(NULL);
  rec.ut_time = t;
  ```
- `struct utmp` 大小：len 用 `sizeof(struct utmp)` 计算，不要写死数字（who 文档里也强调过）；
- 图形会话的记录 `ut_line` 可能是 `:0`、`seat0` 而不是 `ttyN`，测试时以 `who` 输出的第 2 列为准。

## 七、小结

- **对同一个文件既读又写**的完整闭环：`open(O_RDWR)` → 循环 `read` 找目标记录 → 内存中修改 → `lseek` 回退 → `write` 覆盖写回 → `close`；
- 新学的系统调用只有一个：**lseek**——它移动文件位置指针，偏移可为负，`SEEK_SET/CUR/END` 三种基准；
- 关键概念：**位置指针属于文件描述符**，随每次读写自动后移，"读了再想改写刚才那条"必须先 lseek 退回去；
- 系统调用层层检查返回值 + errno 错误处理，在修改系统文件的程序里不是洁癖，是必需。
